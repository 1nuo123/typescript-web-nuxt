## 二、差距清单(盘点发现的真实缺陷)

### A. 契约正确性缺陷(会导致运行时 422/502 或功能失效)

- [ ] A1 `users.replaceRoles` 请求缺少后端必填字段 `confirmation`(min 1/max 64,须等于 `confirm-admin-grant`),当前必然 422。
- [ ] A2 `roles.replaceScopes` 同上,缺少必填 `confirmation`。
- [ ] A3 `roles.create` 缺少可选 `confirmation`,当 scope_codes 含受保护 scope 时后端要求二次确认,当前必然 422。
- [ ] A4 用户列表过滤参数前端发送 `active`,后端为 `is_active`,过滤静默失效。
- [ ] A5 业务角色列表 `expectedOperationName` 前端为 `business_role_list`,后端实际返回 `role_list`,信封校验必然抛错(502 契约错误)。
- [ ] A6 审计查询 `action` 为自由文本,后端是枚举 `AdminAuditAction`,任意非法值直接 422;应改为下拉枚举。
- [ ] A7 `AdminAuditResult.Failure` 前端值 `failure`,后端为 `failed`。
- [ ] A8 运维任务类型 `AdminTaskRuntimePayload`/`AdminTaskExecutionRecordPayload`/`AdminTaskRegistrationPayload`/`AdminTaskDispatchResultPayload` 字段与后端契约大面积不符(如后端为 `task_backend`/`task_runtime_mode`/`record_id`/`task_name`/`registration_backend` 等),页面展示的 `runtime.backend`、`item.backend` 均为不存在字段。
- [ ] A9 运维日志 `AdminLogRecordPayload` 缺 `event_id/source_module/source_component`,`AdminSecurityEventPayload` 结构错误(后端为 `event_id/log_level/log_message/.../security_event` 嵌套信封,前端摊平的 `event_type/severity/decision/ip_digest` 不存在于顶层)。
- [ ] A10 `logs.securityEvents` 中的 legacy `records` 兼容垫片对应的旧结构在后端不存在(`extra=forbid`),属于凭空防御,移除并同步测试。
- [ ] A11 `HealthProbePayload` 前端为 `probe_kind/checks`,后端为 `status/ready`;`SystemOverviewAdminPayload` 前端为 `app_name/debug/resources: Record`,后端为 `title/application_name/version/environment/enabled_modules/ready/resources: list`。
- [ ] A12 任务执行查询 `status`、日志查询 `level/event_kind` 为自由文本,后端为严格枚举,改为下拉枚举避免 422。

### B. 功能闭环缺口

- [ ] B1 用户/角色/审计列表有 `total/page_size/offset` 但页面无分页控件,补统一分页组件。
- [ ] B2 用户停用原因为写死常量,改为可输入(带默认值),对齐后端 1..256 校验。
- [ ] B3 高危操作(角色 scope 替换/用户角色替换/受保护 scope 角色创建)提供确认短语输入与提示,避免盲发。
- [ ] B4 任务派发 `payload_json` 无客户端 JSON 校验,先 `JSON.parse` 预检并展示派发结果详情。
- [ ] B5 系统概览页展示后端真实字段(版本/环境/启用模块/资源状态列表)。

### C. 样式体系(纯 CSS → TailwindCSS)

## 三、方案要点

### 3.1 API 层

- 保持 `useApi`/`useAuthenticatedApi`/`envelope.ts` 既有分层(已具备信封校验、401 刷新重放、外部地址防护),仅修正契约参数与类型。
- `types/admin-identity.ts` 增加 `confirmation` 字段与 `ADMIN_IDENTITY_GRANT_CONFIRMATION_PHRASE` 常量导出(单一来源,页面与服务共用);移除后端不存在的 `BusinessRoleList` 操作名。
- `types/admin-audit.ts` 增加 `AdminAuditAction` 枚举并将查询 `action` 类型收敛为枚举;`AdminAuditResult.Failure` 改为 `failed`。
- `types/admin-ops.ts` 依据后端 `contract_admin_task.py`/`contract_admin_log.py`/`contract_admin_settings.py`/`contract_system_overview.py`/`contract_health_probe.py` 全面重写载荷类型,并补 `TaskExecutionStatus`/`TaskExecutionStage`/`TaskBackend`/`LogLevel`/`LogEventKind`/`SecurityEventSeverity`/`SecurityEventDecision` 等枚举。
- `services/api/admin.ts`:`is_active` 参数、业务角色 operation_name、confirmation 透传、移除 legacy 垫片。

### 3.2 Tailwind 设计令牌(v4)

```css
@import 'tailwindcss';
@theme inline {
  --color-canvas / --color-surface / --color-surface-muted / --color-elevated
  --color-ink / --color-ink-muted / --color-line / --color-line-strong
  --color-primary(-strong/-soft) / --color-accent(-soft) / --color-warning(-soft) / --color-danger(-soft)
  --font-sans / --font-mono
}
:root{...浅色变量} :root[data-theme='dark']{...深色变量}
```

- 工具类示例:`bg-surface text-ink border-line`、`text-primary`、`bg-danger-soft`;组件不写死色值。
- base 层仅保留:document 背景渐变、链接下划线、焦点可见环、`::selection`、`prefers-reduced-motion`、`.sr-only`(a11y)与 skip-link 两个可访问性钩子。

### 3.3 组件与页面

- 页面结构不变(路由/权限中间件/布局既有设计良好),只做样式迁移 + 上述功能补缺。
- 表格统一 `AdminTable`;工具栏统一 `AdminToolbar`;卡片统一 `AdminCard`;列表页统一 `AdminPagination`;状态展示统一 `BaseBadge`。
- 高危操作确认短语输入统一提示文案:「输入 confirm-admin-grant 以确认高危授权变更」。

### 3.4 验收标准

1. `pnpm verify` 全链路(format/lint/typecheck/unit/coverage/build/e2e)全绿。
2. `rg "<style" app` 仅允许 0 处业务样式块(如确有无法用工具类表达的键帧等,收敛到 main.css base/utilities 层)。
3. 对运行中后端完成一次登录 → 拉取用户列表的真实请求冒烟,无契约错误。
4. 文档回写完成,清单全部勾选或标注偏差原因。
